
## 개요

Streaming은 Next.js(App Router)에서 사용하는 서버 렌더링 방식 중 하나로, HTML을 한 번에 완성해서 보내는 것이 아니라 준비된 부분부터 순차적으로 나눠서 전송하는 방식이다.

기존 SSR은 모든 데이터가 준비될 때까지 기다린 뒤 HTML을 한 번에 응답하지만, Streaming은:

* 먼저 준비된 UI를 즉시 전달하고
* 나머지는 나중에 이어서 전달

하는 구조다.

이 과정은 React의 Suspense와 함께 동작한다.

⸻

## 예시

기존 방식 (Streaming 없음)

1. 서버 요청
2. PostFeed (느림)
3. Weather (빠름)
4. 둘 다 완료될 때까지 대기
5. HTML 한 번에 전송

→ 느린 데이터가 전체를 지연시킴

⸻

Streaming 방식

1. 서버 요청
2. Weather 먼저 완료 → 즉시 HTML 전송
3. PostFeed 아직 → fallback 전송
4. PostFeed 완료 → 나중에 추가 전송

→ 화면이 점진적으로 완성됨

⸻

## 사용 예시

1) 대시보드

- 사용자 정보
- 통계 그래프
- 최근 활동

각 영역이 서로 독립적일 때:

* 빠른 데이터 먼저 표시
* 느린 데이터는 나중에 채움

⸻

2) 블로그 + 위젯 구조

- 게시글 목록
- 날씨
- 광고

→ 일부만 먼저 보여줘도 UX 개선 가능

⸻

3) 여러 API를 사용하는 페이지

- 내부 API
- 외부 API (느림)

→ 외부 API 때문에 전체가 느려지는 것을 방지

⸻

언제 사용하는가

* 데이터 요청이 여러 개일 때
* 응답 속도가 서로 다른 API가 섞여 있을 때
* 초기 화면을 빠르게 보여주고 싶을 때
* 대시보드 / 피드 / 위젯 구조

⸻

언제 사용하지 않는가

* 데이터가 하나뿐인 단순 페이지
* 전체가 동시에 렌더링되어야 하는 경우
* Suspense 분리가 불필요한 구조
